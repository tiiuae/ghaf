# Secure A/B image updates

The shared core owns authenticated payloads, target/generation policy,
transactional slots and boot health. Platform adapters own initial storage,
enrollment, firmware and recovery. The Orin and x86 adapter PRs each provide
their own platform testing guide.

## Invariants

- Authenticate the manifest and UKI and enforce target, generation, sizes and
  hashes before storage mutation. Lock before discovering slots.
- Never write the active root/verity pair. Bound inactive writes by fixed
  platform capacities and verify dm-verity before committing final names.
- Install the complete UKI atomically and commit candidate-specific boot
  selection last. Installation returns reboot-required; it never reboots.
- Allow three trial attempts. Bless only after storage and configured core
  MicroVM health checks; accepted generation never decreases.
- Rollback replaces only the immutable system pair, not shared `/persist`.
  Downgrades require an explicit debug-only override.

## System-slot model

```text
ESP -> selected UKI
system partition -> optional LUKS2 -> VG pool
  root_<version>_<hash-fragment> / verity_<version>_<hash-fragment>
  second root/verity pair + persistent platform volumes
```

Transactions use `root_staging_<hash-fragment>` and
`verity_staging_<hash-fragment>`. Recognizable inactive staging/partial commits
are recoverable on retry; ambiguous layouts stop. Fixed root/verity capacities
must accommodate both generations; oversized payloads are rejected, not resized
by consuming persist. Partitioning and enrollment remain adapter policy.

## Pure trust configuration

The lockable, non-flake `secure-ab-build-config` input contains only
`config.json`, `PK.crt`, `KEK.crt`, `db.crt` and `update.pub`. Its JSON specifies
schema version 1, trust `external`, a positive generation, and optional boolean
`inject_boot_health_failure` (debug-only). Evaluation reads neither environment
variables nor private key directories. The repository template has no keys:
all secure images, including debug, require external public trust.

Run build-host commands from the root of the Ghaf checkout being tested, in
Bash with Nix, `jq`, Python 3 and GNU coreutils available. The platform guides
supply the exact package and generation. Enter `nix develop` in that checkout
to obtain its pinned `jq`, Python and other development tools before defining
the commands below. Each complete command block runs in a subshell: failures
stop that step without exiting your terminal. Variables do not survive the
block. Record printed output paths and enter them when the next step prompts;
you can resume from a new shell without reconstructing earlier variables.
Local paths do not transfer between machines.

Create development keys once outside Git and the Nix store. Reuse that same key
directory for every image/update installed on a device enrolled with its trust:

```bash
(
set -euo pipefail
umask 077
export GHAF_DEV_KEY_DIR="$HOME/.local/share/ghaf-dev-keys"
if [ ! -d "$GHAF_DEV_KEY_DIR" ]; then
  nix run .#ghaf-dev-keygen -- --output "$GHAF_DEV_KEY_DIR"
fi
printf 'Signing-key directory: %s\n' "$GHAF_DEV_KEY_DIR"
)
```

`ghaf-dev-keygen` creates private `PK.key`, `KEK.key`, `db.key`, `update.key`,
their public certificates/key, and UEFI `.esl`/`.auth` enrollment files in that
directory. An existing incomplete directory must be investigated, not silently
replaced with another trust set. The generator writes the raw 32-byte Ed25519
`update.pub`; the exporter below only copies public files.

For the generic **update-payload** example below, select a sysupdate/OTA package
from the platform guide and a generation newer than the device's accepted value.
This is an alternative to the platform's build recipe, not an additional build
step to run before it:

```bash
(
set -euo pipefail
read -r -p 'Existing signing-key directory (absolute path): ' GHAF_DEV_KEY_DIR
read -r -p 'Update payload package from the platform guide: ' PLATFORM_TARGET
read -r -p 'New generation: ' GENERATION
PUBLIC="/var/tmp/secure-ab-generation-$GENERATION"
nix run .#ghaf-secure-ab-config -- --key-dir "$GHAF_DEV_KEY_DIR" \
  --generation "$GENERATION" --output "$PUBLIC"
timeout 2h nix build \
  --override-input secure-ab-build-config "path:$PUBLIC" \
  ".#$PLATFORM_TARGET" -o result-update
)
```

The exporter creates `$PUBLIC/config.json` and the four public trust files;
it rejects an existing output directory. The build creates `result-update`, a
symlink to the immutable Nix output containing the unsigned manifest/artifacts
consumed by the next section. Initial-disk and installer outputs are different
artifacts and must use the platform guide's initial-install recipe.

| Producer | Output and location | Consumer |
| --- | --- | --- |
| Key generator, build host | Private keys and public trust in `$GHAF_DEV_KEY_DIR` | Local signers; only exported public files enter builds/devices |
| Config exporter, build host | Fresh `$PUBLIC` directory with generation and public trust | Nix `secure-ab-build-config` input |
| Update build, build host | `result-update/*.manifest` and three named artifacts in the Nix store | `ghaf-sign-update` |
| Update signer, build host | `$SIGNED_DIR`: signed manifest, its `.sig`, root/verity payloads and signed UKI | HTTP staging or OCI push |
| Fetch, `net-vm` | Published bundle under shared `/persist/sysupdate`; prints its location | Host validation, using the same path |
| Install, Ghaf host | Inactive slot plus trial UKI and one-shot EFI selection | Next boot and health service |
| Health service, Ghaf host | Accepted-generation file and promoted/blessed entry, or fallback | Next generation selection and test verdict |

The updater also accepts a 64-character hexadecimal Ed25519 public key.
Missing/inconsistent public files fail; there is no bundled key or unsigned
fallback. Release wrapper flakes should lock the public input and make Ghaf's
input follow it. Never mutate a public input already used for a published image.

### Proposed CI integration

The dedicated secure-image CI flow below is proposed; it is not implemented. Secure adapter targets remain exposed
in `packages`; evaluating their derivations requires a CI-owned, locked public
configuration supplied through `--override-input secure-ab-build-config`.
Future jobs should inject that configuration, run package checks and build targets sequentially under
`timeout 2h`. Keep signing secrets outside builds. Separate hardware jobs must
select authorized devices and record the complete acceptance matrix before
promotion; missing configuration must fail, not substitute another target.

## Signed manifest v2

A bundle has one `ghaf_<version>_<hash>.manifest`, its `.manifest.sig`, and the
three named artifacts. The detached signature is raw 64-byte Ed25519 over the
exact manifest bytes; the UEFI db key independently signs the UKI.

| Fields | Contract |
| --- | --- |
| `manifest_version` | 2 |
| `system`, `build-system` | Target and native/cross-builder Nix systems |
| `target`, `version`, `generation` | Exact authorized target, version string, positive monotonic generation |
| `meta`, `root_verity_hash` | Metadata object and 64-hex-character dm-verity root hash |
| `root`, `verity`, `kernel` | Objects containing `file`, `sha256`, `packed_size`, `unpacked_size` |
| Artifact `file` | Distinct safe basename relative to the manifest; no collision with metadata |
| Artifact sizes | Positive byte counts; packed bounds transport, unpacked bounds destination |
| UKI binding | Embedded `ghaf.storehash` and `ghaf.generation` match the signed manifest |

Root/verity names are `ghaf_{root,verity}_<version>_<hash>.raw.zst`; the UKI is
`ghaf_kernel_<version>_<hash>.efi`. Sign into a new output directory:

```bash
(
set -euo pipefail
read -r -p 'Existing signing-key directory (absolute path): ' GHAF_DEV_KEY_DIR
manifests=(result-update/*.manifest)
test "${#manifests[@]}" -eq 1 && test -f "${manifests[0]}"
MANIFEST="${manifests[0]}"
GENERATION=$(jq -er .generation "$MANIFEST")
SIGNED_DIR="/var/tmp/ghaf-signed-update-$GENERATION"
nix run .#ghaf-sign-update -- --key-dir "$GHAF_DEV_KEY_DIR" \
  --input "$MANIFEST" --output "$SIGNED_DIR"
SIGNED_MANIFEST="$SIGNED_DIR/$(basename "$MANIFEST")"
printf 'Signed manifest: %s\n' "$SIGNED_MANIFEST"
)
```

Record the printed signed-manifest path for delivery; the manifest is not
renamed to `manifest.json` by the signer. Use a fresh signing directory for each
candidate.

The signing input must be the trusted, immutable Nix build output (`result-update`
may be a symlink to it). Do not sign from a writable staging directory: artifact
hashes cannot protect a manifest that an attacker can also replace.

The signer checks key correspondence and artifact-name collisions, copies each
artifact and verifies it against the input manifest's SHA-256 before signing.
It signs the verified UKI copy, recomputes artifact metadata and signs the manifest last.

## Shared image-construction tools

Initial disk creation runs in a disposable Nix build VM with its own scratch disk.
`ghaf-initialize-verity-lvm` validates the manifest and decompressed payload lengths,
then uses stock `pvcreate`, `vgcreate` and `lvcreate` to create the fixed A/B
slots, with an optional outer LUKS2 container created by `cryptsetup`. Optional swap and persist filesystems use stock formatters.
The build host needs KVM; it does not need root access to host storage devices.

The build-time LUKS volume key is a transport key shared by every copy of the
image. Adapters must replace it with a device-unique volume key through LUKS2
reencryption during per-device provisioning before accepting sensitive persistent
data. Plain images instead create their LUKS volume key during deferred encryption
on the device. Enrolling a TPM, FIDO2, DUK or recovery credential and removing the
bootstrap keyslot only changes how the existing volume key is unlocked; it does
not replace that key.

The shared VM wrapper keeps large payloads on host-backed scratch storage. Platform
adapters own GPT/ESP layout and publish the compressed disk only after the VM
finishes successfully. Private signing remains outside the Nix build. The core
storage test activates the resulting volumes, reads payloads, renames an inactive
slot, and grows and remounts persist. The build no longer depends on ghafpkgs #378
or a custom LVM metadata writer or LUKS header conversion.

## Delivery and installation

```text
build/sign -> net-vm fetch -> shared persist -> host validation/install
           -> manual reboot -> counted trial -> health acceptance or rollback
```

Production delivery uses `ota-update registry` with authenticated HTTPS and
read-only device credentials. `ghaf-fetch-update` is a debug-only static-HTTP
helper: fixed metadata/artifact caps, declared packed-size limits and exact
final-size checks precede atomic publication. Fetching never authorizes install. Registry `pull --validate` checks artifact
integrity, not the detached signature, UKI trust or device generation policy;
`ota-update image validate` on the host is still required. Registry `--install`
is disabled for signed manifest v2.

On the host, run `ota-update image validate`, then
`ota-update image --dry-run install`, then `ota-update image install`, each with
`--manifest PATH`. The first command authenticates the manifest, target,
artifacts and UKI; it does not reject an already accepted or older generation.
The installation dry-run additionally checks accepted-generation policy and
storage state without writing slots. Stop on failure from either command.
The locked transaction verifies
signatures/policy, discovers slots, snapshots/rechecks the network-writable UKI,
recovers staging, supervises decompression, verifies dm-verity, commits LV names,
atomically installs the three-attempt UKI, then changes boot selection.

### Static HTTP lab delivery

**Build host, any Bash session in `nix develop`.** Enter the signed-manifest
path printed by the signer; its containing directory supplies the artifacts.
Do not point to an initial disk or unsigned output.
Choose the build-host address reachable from the target's `net-vm` using
`ip -br -4 address`, and permit TCP port 18080 on that lab interface.

The helper expects `manifest.json` and `manifest.json.sig`. Create those names
from the signed bytes, without reformatting the JSON, in a public-only staging
directory on disk (the payload can be several GiB):

```bash
(
set -euo pipefail
read -r -p 'Signed manifest path printed by the signer: ' SIGNED_MANIFEST
SIGNED_DIR=$(dirname -- "$SIGNED_MANIFEST")
test -s "$SIGNED_MANIFEST.sig"
GENERATION=$(jq -er .generation "$SIGNED_MANIFEST")
ip -br -4 address
read -r -p 'Build-host IP reachable from net-vm: ' BUILD_HOST_IP
HTTP_ROOT="$(mktemp -d /var/tmp/ghaf-update-http.XXXXXX)"
install -m 0644 "$SIGNED_MANIFEST" "$HTTP_ROOT/manifest.json"
install -m 0644 "$SIGNED_MANIFEST.sig" "$HTTP_ROOT/manifest.json.sig"
for kind in root verity kernel; do
  artifact="$(jq -er --arg kind "$kind" '.[$kind].file' "$SIGNED_MANIFEST")"
  cp --reflink=auto -- "$SIGNED_DIR/$artifact" "$HTTP_ROOT/$artifact"
done
printf 'HTTP origin: http://%s:18080\nGeneration: %s\n' "$BUILD_HOST_IP" "$GENERATION"
python3 -m http.server 18080 --bind "$BUILD_HOST_IP" --directory "$HTTP_ROOT"
)
```

Output: a foreground server exposing exactly the signed manifest/signature and
three artifacts. Leave that terminal running while fetching. Private keys are
never copied to `$HTTP_ROOT`.

**Separate `net-vm` shell.** Connect using the platform's device address and
[SSH access procedure](/ghaf/dev/ref/ssh#connect) and verify that this is the
network VM: its internal interface has address `192.168.100.1`; its hostname
is generated as `ghaf-…`, not literally `net-vm`. Enter the origin and
generation printed above. These values are copied
explicitly; build-host variables do not exist in this shell:

```bash
(
set -euo pipefail
hostname
ip -br -4 address
read -r -p 'HTTP origin printed by the build host: ' UPDATE_HTTP_ORIGIN
read -r -p 'Generation printed by the build host: ' GENERATION
test -w /persist/sysupdate
ghaf-fetch-update "$UPDATE_HTTP_ORIGIN" "$GENERATION" /persist/sysupdate
printf 'Host manifest: /persist/sysupdate/http-generation-%s/manifest.json\n' "$GENERATION"
)
```

Output: `/persist/sysupdate/http-generation-N/` containing `manifest.json`,
`manifest.json.sig`, the three artifacts and `fetch.complete`. Here `N` is the
entered generation; the helper's directory argument does not authenticate it.
The host must still check the signed manifest's generation and target.

The configured virtiofs share makes that same path visible on the Ghaf host;
no SCP from `net-vm` to the host is needed. Enter the printed **host manifest**
path in the platform's host-install step. If `/persist/sysupdate` is absent or
not writable in `net-vm`, investigate the share instead of downloading elsewhere
and assuming the host can see it. A fetch refuses to replace a published
directory. After a successful fetch, stop the build-host server with Ctrl+C.
A failed fetch leaves only temporary state, not a ready-to-install bundle.

## Boot health and rollback

This policy requires the GIVC fix in
[PR #512](https://github.com/tiiuae/ghaf-givc/pull/512), commit
`e68d2d23598a1aba6da9696f4ecb250dea848e25`, or a revision containing it. Check
`nodes.givc.locked.rev` in `flake.lock`; the current pin contains the merged
fix. Devices still running the older `3755b99` updater promote the trial during
installation and need the updated updater before rollback testing.
The install dry-run must end in `bootctl set-oneshot`, not `set-default`.

Trial UKIs are named `ghaf-<version>-<hash>+3.efi`. Installation selects the
candidate for one boot while preserving the last healthy default. A healthy
trial is promoted to its exact UKI name.

`ghaf-boot-health.service` checks LUKS, dm-verity, store/persist mounts, configured
core VMM services and kernel generation; AppVMs/login are excluded. It promotes
the entry, atomically persists accepted generation, then blesses last. A retry
after acceptance persistence finishes promotion/blessing without lowering state.
Unhealthy trials re-arm while attempts remain and reboot; exhaustion selects
the blessed fallback. Failure before the health service can re-arm the trial
returns to the fallback on the next boot, so early corruption need not consume
all three attempts. Hard hangs additionally require a proven platform reset.
Do not set the trial as the persistent default: `LoaderEntryDefault` can select
exhausted entries, as described by the
[systemd boot loader interface](https://systemd.io/BOOT_LOADER_INTERFACE/).

The health gate checks VMM service activity; guest-agent liveness is not
currently checked.
